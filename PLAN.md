списком и редактором через Navigation 3.

### Критерии готовности

- Заметки хранятся в Room и переживают перезапуск приложения.
- Repository предоставляет реактивный `Flow` заметок.
- Новая заметка создаётся из заголовка и/или текста.
- Для заметки без заголовка формируется устойчивое уникальное имя `Заметка N`.
- Реализованы loading, empty, content и error-состояния.
- Навигационные контракты находятся в `api`, реализация — в `impl`.
- Koin-граф и значимое поведение покрыты JVM-тестами.

### Промпт исполнителю

## 4. Просмотр, редактирование и удаление заметок — ✅

### Задача

Добавить открытие существующей заметки в Reading, переход в Editing без нового
navigation destination, отмену несохранённых изменений, обновление записи и
режим удаления заметок. Хранить отдельно даты создания и изменения и выводить
недавно изменённую заметку выше.

### Критерии готовности

- `NoteEditorRoute(noteId)` загружает существующую запись и открывает Reading.
- Edit переводит тот же ViewModel в Editing.
- Back из Editing восстанавливает последнее сохранённое состояние.
- Save изменяет существующую запись без дубликата и возвращает Reading.
- Дата создания сохраняется, дата изменения обновляется.
- Delete mode отключает открытие карточек и позволяет удалять записи.
- Ошибки загрузки, обновления и удаления не приводят к потере данных.
- Room migration сохраняет существующие заметки.

## 5. Изображения в заметках — ✅

### Задача

Реализовать одно постоянное изображение на заметку: выбор через системный
picker, съёмку камерой, временный draft, безопасное сохранение во внутреннем
хранилище, превью, замену и удаление. Room хранит только непрозрачное имя файла.

### Критерии готовности

- `image_file_name` nullable и содержит только сгенерированное приложением имя.
- Внешние и временные URI никогда не сохраняются в Room.
- Выбранный/снятый файл сначала попадает в staging.
- Новый файл финализируется до Room write; при ошибке БД он удаляется, а старый
  остаётся действующим.
- При удалении вложения или заметки сначала меняется Room, затем удаляется файл;
  возможный orphan безопасно очищается reconciliation-механизмом.
- Отмена выбора, съёмки, создания или Editing очищает соответствующий draft.
- Photo Picker/SAF не требует лишних storage permissions; камера использует
  узко настроенный FileProvider и корректный permission flow.
- ViewModel не зависит от Activity, `ContentResolver`, launcher или permission
  API; файловые операции скрыты за тестируемой границей.
- Декодирование происходит вне main thread, с ограничением размера и учётом
  ориентации; сторонняя image-loading библиотека не используется без согласия.
- Thumbnail и preview соответствуют утверждённому дизайну и доступны в Reading,
  Editing и списке заметок.

## 7. Bottom Navigation и корневые заглушки — ✅

Создать app-owned верхнеуровневую навигацию с тремя вкладками Notes, Tasks и
Settings. Notes остаётся рабочей фичей; Tasks и Settings получают минимальные

проверять внутри приложения.

### Критерии готовности

- Созданы `feature:tasks:api/impl` и `feature:settings:api/impl` без пустых
  domain/data/DI-пакетов.
- Bottom Navigation содержит ровно три вкладки из утверждённого дизайна.
- `app` владеет выбранной вкладкой, корневыми back stack и `NavDisplay`.
- Состояние и back stack вкладок сохраняются при переключении.
- Повторный выбор вкладки возвращает её к корню согласно согласованному
  поведению.
- Note Editor остаётся вложенным экраном без Bottom Navigation.
- Заглушки используют ресурсы, дизайн-систему и Preview.

### Промпт исполнителю
